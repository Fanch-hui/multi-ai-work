# 客户健康评分方法

适用于规则评分和人工复核。先采用用户已批准的口径；没有历史验证的规则分不称为流失概率。

## 指标定义

| 维度 | 可用指标 | 必须核实 |
|---|---|---|
| 使用 | 活跃座席/付费座席、关键工作流完成、功能使用 | 同一期间、活跃定义、分母和季节性 |
| 支持 | 未结严重问题、解决耗时、重开情况 | 严重度、开始/结束时点、是否含等待 |
| 关系 | 负责人参与、使用者反馈、续约意向 | 原话来源、时点、角色与未确认意向 |
| 价值 | 目标实现、经确认节省工时、成果采用 | 基线、对照和可归因范围 |

工单数量高可反映问题多或深入使用，不预设数量越低越健康。单次0–10推荐意愿回答不是总体NPS；总体NPS需要按9–10推荐者比例减0–6贬损者比例计算，范围-100至100。

## 规则评分

1. 每个分项保留原始值、映射公式、单位、期间、数据来源；分项得分映射为0–100必须获批准。
2. 权重非负、合计1。得分为各权重与分项得分的乘积之和。禁止在没有说明的情况下改权重以凑出总分。
3. 任一必需分项缺失时，记录已知分项、已知权重合计和已知加权小计，综合分未知；未知意向不自动映射成50分。
4. 颜色门槛、趋势变化阈值和跟进频率来自用户配置。不同客户口径变化时先做可比性说明。
5. 规则分或颜色只用于排序与讨论，续约风险还需结合业务价值、负责人变化、严重问题及实际合同信息。

## 计算输入

`scripts/weighted_health.py input.json` 使用如下结构：

```json
{"accounts":[{"id":"A01","period":"2026-10","metrics":[{"name":"使用","weight":0.5,"score":80},{"name":"支持","weight":0.3,"score":null},{"name":"关系","weight":0.2,"score":70}]}]}
```

该例已知权重0.7、加权小计54、综合分未知。它不说明未知支持分是好或坏。通过 App 返回的Python实际路径运行，命令路径与输入必须在授权工作范围。

## 输出复核

并列前后期间的原始分母、分项、分数、来源和缺口；将风险、建议措施与实际执行分开。用后续真实结果检验规则和阈值，变更口径保留版本。
