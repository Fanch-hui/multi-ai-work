# 工程履约证据与通知资料

## 输入与依据

仅使用当前任务提供或明确授权读取的项目、合同和企业资料。先核对记录编号、版次、数据日期、计量单位和待确认项。

## 工作流程

1. 确认项目、用户所代表一方、合同版次及资料范围，建立合同条款原文、事件记录、通知、签收和费用凭据之间的对应索引。
2. 按事件日期、知悉日期、通知发出日期和签收日期分别编排时间线；每项引用文件编号、位置、版次和原文，分开记录双方陈述、客观记录和缺失证据。
3. 通知期限、起算条件、送达方式和收件人只从实际合同及已确认规则提取。起算或送达存在歧义时，列出不同解释及缺失资料，不给出唯一的已满足或已逾期结论。
4. 采用上游 legal-response 的模板变量、事项编号、合同引用、事实核对、保全范围与升级复核流程，制作履约通知或补充资料函草稿；使用 templates/notice-evidence.md 记录依据、待补项和审核人。
5. 成本逐项列数量、单价、期间和凭据，检查重复费用与已付款抵扣；申请额、审核额、批准额和付款额分列，工期影响单列。
6. 汇总履约证据包、资料缺口与审阅清单。涉及争议、权利放弃、责任承认或新增承诺时，明确需要商务负责人或法务审阅的段落。

## 工程适用范围

- 仅生成供审阅的草稿与证据资料，未经有权人确认不宣布索赔成立、金额应付或责任已认定。
- 以本项目合同、已确认法域和企业批准模板为依据，不套用上游隐私、诉讼、保险示例的期限或措辞；不自行标注具有法律特权的通信。
- 资料保全只提出清单与建议，不修改、删除或冻结原始资料；原始编号、版次与矛盾陈述保持可追溯。

## App 工具与交付

- 文件读取、保存、命令及外部连接均遵守当前成员授权；外部系统接入为可选，不安装组件、不创建外部工单或发送通知。
- 必须计算时，使用 load_workspace_dependencies 返回的运行库路径，通过 run_command 执行工作区内可复核脚本，保留输入、代码与机器结果。
- 以中文交付正文与台账，关联全部原始资料；未知值保留待确认，另存独立成果，保存前核对金额、日期、单位和证据引用。
