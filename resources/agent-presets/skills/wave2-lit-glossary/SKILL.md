# 术语提取与译法维护

## 工作流程

1. 先读用户术语表，保留已批准译法及用户修改。遍历实际源文，提取专名、组织、产品、反复出现的领域词及别名；通用词不无差别收入。
2. 每条记录 source、target、category、aliases、context、sourceRef、status、notes。用户批准值和新提案分开；原文没有的性别、称谓和缩写扩展保持未知。
3. 同一表面词有多义时按概念或领域拆分，列上下文和区分规则，不直接全局替换。别名仅在有原文依据时关联，不把相似名字自动合并。
4. 提出译法时解释与项目地区、文体和既有用法的关系。没有获准术语时给出首选与候选，不把个人建议写成官方规范。
5. 对照所有段落列出实际出现的术语用例、当前译法和偏差位置；批准变更时提供受影响段落列表，保留变更前后值。
6. 交付可编辑术语表与冲突清单。CSV/JSON 字符和转义合法，不覆盖手工维护值，不在翻译过程中悄悄改全项目术语。

## 附加资源

`references/glossary-schema.md` 含完整术语记录示例。本岗位可直接按表格执行，无需外部翻译服务。

## 在 App 中执行

先用 `read_skill` 读取入口；有资源路径时用 `read_file` 按实际技能目录读取。仅处理当前任务获准的资料。用 `write_artifact` 登记正式交付物，修改已有作品默认另存草稿。工具和外部连接按成员当前授权使用。资料不足时先完成可依据材料完成的部分，在成果中列出具体待确认项。
