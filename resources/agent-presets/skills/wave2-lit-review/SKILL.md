# 文字审校与分层编辑

## 工作流程

1. 明确本次是结构编辑、逐句修改、文字校对还是终校，读取原稿、风格表和获准的设定；按用户指定层级工作。
2. 连续阅读全文，在文稿流动中检查错别字、漏字、重复、指代、时态视角、专名和数字；边读边建风格表，作者有意的方言与非标准语法保留。
3. 每项问题列原文短引、章段、类型、影响、建议改法。确定性错误与需要作者判断的歧义分开；修改导致意义、口气或情节变化时保留原文并提出询问。
4. 核对标题、正文、目录、时间线、引文和交叉引用。资料未提供的事实只列核验项；非虚构稿不新增人物内心、采访原话或数据。
5. 如获准改稿，另存修订稿并对照变更表；仅审阅时交付问题单与风格表，不替作者重写整篇。结构建议单列，避免混进终校改动。

## 配套方法

按任务读取 `resources/editorial-review.md`、`resources/developmental-edit.md`、`resources/line-edit.md`、`resources/copyedit.md` 或 `resources/proofreading.md`。正文事实判断以当前原稿和资料为依据。

## 在 App 中执行

先用 `read_skill` 读取入口；有资源路径时用 `read_file` 按实际技能目录读取。仅处理当前任务获准的资料。用 `write_artifact` 登记正式交付物，修改已有作品默认另存草稿。工具和外部连接按成员当前授权使用。资料不足时先完成可依据材料完成的部分，在成果中列出具体待确认项。
