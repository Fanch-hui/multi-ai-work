# 工程变更与签证台账

## 输入与依据

仅使用当前任务提供或明确授权读取的项目、合同和企业资料。先核对记录编号、版次、数据日期、计量单位和待确认项。

## 工作流程

1. 读取全部资料，建立项目合同、指令、图纸、往来记录的编号与版次索引；把原范围与拟变更范围并列。
2. 采用上游 change-request 的请求、影响分析、实施依赖和批准记录结构，逐项提取提出方、原因、部位、费用、工期、质量与施工接口影响。
3. 将提出、报价、审核、批准、实施、计量和付款分别登记。每个状态附实际证据、日期、签认人和权限依据，不能从后一动作倒推前一批准。
4. 按项目明确的数量、单价、税费和取费口径计算。将未批准报价、已批准变更、实际支出和已付款分列，标明重复项、缺失项及是否纳入合同批准总额。
5. 说明执行的前置条件、责任人和需补资料。工程撤回或返工仅登记已有指令和影响，不套用 IT 系统回滚动作。
6. 用 templates/change-register.md 组织变更台账、影响说明和待确认清单；核对同一编号在各表中的金额、版次和状态一致。

## 工程适用范围

- 技术方案、工程量口径、签证效力、计价规则与签认权限以实际项目依据为准，未提供的默认费率和批准规则保留待确认。
- 签收、会议提议和施工事实分别记录，不写成金额批准；未批准变更单独统计。
- 上游中的状态、风险等级和批准表是结构模板，只有资料支持时才填写为已批准或已完成。

## App 工具与交付

- 文件读取、保存、命令及外部连接均遵守当前成员授权；外部系统接入为可选，不安装组件、不创建外部工单或发送通知。
- 必须计算时，使用 load_workspace_dependencies 返回的运行库路径，通过 run_command 执行工作区内可复核脚本，保留输入、代码与机器结果。
- 以中文交付正文与台账，关联全部原始资料；未知值保留待确认，另存独立成果，保存前核对金额、日期、单位和证据引用。

## 配套资源

- `upstream/skills/change-request/SKILL.md`：完整上游技能，可按任务需要读取相关流程与模板；适用口径以本中文入口和实际项目资料为准。
- `upstream/CONNECTORS.md`：上游连接类别说明，类别名称不表示 App 已配置或授权对应服务。
- `templates/change-register.md`：本地工程交付结构。
