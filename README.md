# multi-AI work

本地优先的个人 AI 团队工作台。对话、任务、成果和长期记忆保存在本机；模型通过 Antigravity CLI（agy）、ChatGPT、Qoder CN 或自定义 API 连接。桌面应用使用 Electron、React、TypeScript 和 SQLite。

## 启动与构建

需要 Node.js 22.23.0 或更高版本、pnpm 11.25.0。首次安装与下载运行时需要网络。

```sh
pnpm install --frozen-lockfile
node node_modules/electron/install.js
pnpm desktop
```

常用命令：

| 命令 | 用途 |
| --- | --- |
| `pnpm dev` | 启动开发 Core 与 UI，访问 `http://127.0.0.1:5173` |
| `pnpm typecheck` | TypeScript 检查 |
| `pnpm test` | 核心、协议适配和工具测试 |
| `pnpm build` | 编译 Core、Electron 与 UI |
| `pnpm package:mac` | 在 macOS 生成应用目录、DMG 和更新 ZIP，输出到 `release` |
| `pnpm package:win` | 在 Windows 生成 NSIS 安装包，输出到 `release` |

`pnpm desktop` 构建本机应用后启动，使 SQLite 与 Electron 使用匹配的运行时。桌面数据目录可在“连接与设置 → 运行与备份”查看。开发模式使用项目内的 `.data`，API/OAuth 凭据仅留在当前进程，重启后需重新提供；日常使用请启动桌面应用。agy 保留本机 HOME，复用原生登录与系统 Keyring；Qoder 使用连接专用 profile。

## 应用更新

桌面应用每次启动检查一次更新，也可在“连接与设置 → 运行与备份 → 应用更新”手动检查。发现新版时，品牌名称右侧显示下载图标；下载完成后切换为重启更新图标。安装前须完成或停止所有任务。更新替换应用程序，保留本机工作台数据。

更新支持安装在 `/Applications` 的 macOS arm64 应用与 Windows x64 NSIS 安装版本。发布流程在两平台安装包门禁通过后生成 `desktop-release-materials`，包含更新 ZIP、EXE、`latest.json` 和 `SHA256SUMS.txt`；将这些文件上传至同版本 `v<version>` 的 GitHub Release 后，客户端即可检查到更新。本地可运行 `node scripts/ci/release-metadata.mjs <产物目录>` 生成清单，目录须同时包含当前版本的 macOS ZIP 与 Windows EXE。

## 配置连接

在“连接与设置”添加连接，配置、授权和检测在同一窗口完成。连接可用后，为智能体选择模型和推理强度。账号并发限制按连接配置，已识别的同账号连接共享调度名额。

推理强度优先读取连接返回的模型能力。ChatGPT 目录未提供档位时，按完整模型 ID 从 OpenAI 官方目录补充，不添加当前账号未列出的模型。已有连接可重新检测刷新选项；能力未知时保留默认。

| 连接 | 授权与运行方式 |
| --- | --- |
| Antigravity CLI（agy） | 自动检测本机已安装的 `agy`，复用其现有登录；可指定可执行文件绝对路径。未安装时按官方指引安装，未登录时在终端运行 `agy` 完成授权，再检测连接。 |
| ChatGPT | 点击登录，在系统浏览器完成 Sign in with ChatGPT；使用 Responses 通道。授权结果与模型可用性由服务端决定。 |
| Qoder CN | 使用官方 SDK，支持官方登录或 PAT；可指定兼容 CLI 路径。官方登录按当前连接的专用 profile 指令操作。 |
| 自定义 API | 填写 API 地址和认证方式，选择 Chat Completions 或 Responses。服务须实现所选协议及所用工具能力；没有模型目录时在智能体配置中填写模型 ID。 |

连接会检测显式路径、本机 PATH、常用安装目录与 App 运行时。agy 采用[官方安装与授权流程](https://antigravity.google/docs/cli/install/)，无需在 App 内复制登录凭据；打包时准备兼容的 Qoder CN CLI。检测到文件后仍需验证实际运行和模型目录。安装指引与登录命令按平台提供 POSIX 或 PowerShell 语法。

agy 的上下文、内置工具、原生 MCP 和权限模式由本机 CLI 管理。App 通过原生结构化流传递消息，并按 Bot、会话及代次保存明确的原生会话 ID；续接指定对应会话，不使用全局“继续最近一次会话”。App 提供的团队工具仍由 Core 校验成员授权和审批，下方工具勾选不限制 agy 自身的工具。原生设置可在终端 `agy` 中通过 `/config` 和 `/permissions` 调整，详见 [CLI 配置说明](https://antigravity.google/docs/cli/reference/)与[权限说明](https://antigravity.google/docs/permissions/)。

桌面 API/OAuth 凭据使用 Electron 系统保护存储，不导出到普通数据库或备份。Antigravity/Qoder 上下文由原生运行时管理；ChatGPT/自定义 API 上下文由 App 管理。App 管理的历史在已知上下文窗口达到阈值时尝试生成摘要，保留原始档案；原生运行时压缩能力以连接实际报告为准。

ChatGPT 与自定义 API 遇到短暂过载、连接中断或流超时时，每个模型回合最多自动重试 5 次。界面显示恢复进度；完整工具结果与协议进度持久保存，长时间等待释放执行名额，异常重启后可续接。用户停止或正常退出会取消恢复；结果未知的操作须先核查。重试当前未完成回合可能产生新的模型请求用量。

## 开始工作

1. 在默认主页配置管家 Chief 的连接、模型和推理强度。App 管理的上下文窗口仅在智能体设置，单位为 tokens，留空使用模型目录信息；提前压缩值为百分数。Antigravity/Qoder 显示原生默认及配置方法。
2. 主对话只包含你与管家。侧栏呼叫按钮新建管家主对话，填写名称与工作目录，默认继承管家的模型和推理强度；已有主对话可单独调整配置。历史和会话绑定分别保存。
3. 团队任务由管家查看成员职责，通过 `create_task_group` 创建独立任务群，只加入相关成员。群在侧栏单独展示，你可参与讨论、指定成员或 `@所有人`。点击顶部成员人数查看并管理成员；群内直接讨论，交付汇报回到来源主对话。
4. 在“我的团队”配置成员的头像、角色、模型、App 工具、外部连接和 Skills；头像支持内置动物和上传图片。管家可按执行权限创建或调整成员配置；App 工具权限由用户设置，agy 原生工具权限沿用其本机配置。
5. 主对话、任务群与成员私聊均可附加资料。文件按原始字节归档，成员通过 `read_artifact` 读取；每份最多 25 MiB。
6. Enter 发送，Shift+Enter 换行。侧栏可收起，会话菜单提供归档、恢复和删除；删除会话保留已生成成果。执行与操作审批在“记录”查看，“库”按来源主对话汇集交付成果。

单智能体对话展示累计请求、请求速率、tokens、缓存命中与上下文占用，并可展开详情。请求速率按同批已完成主推理请求的输出量与模型耗时计算，排除工具处理和退避等待；摘要请求单独计数并纳入总用量。请求次数和缓存命中保留已报告部分并展示覆盖范围，缺失数据不补零。估算值标注“约”，服务未报告的值显示未知。agy 的模型目录短时缓存，团队授权检查直接向 Core 核对。

私聊与群聊使用独立上下文。App 文件工具在授权目录内可读取文件、创建成果和更新本任务自产文件。自主执行方式直接执行已授权操作；需审批方式对覆盖原文件、删除文件、命令和外部副作用逐次确认。两种方式都校验文件版本和工作区授权。agy 内置工具按照原生权限执行。取消后以实际停止结果更新状态；外部操作结果未知时，先核查外部系统，再在任务详情确认结果。

内置工具支持读取文本、Markdown、PDF、DOCX、XLSX，生成 Markdown、DOCX、XLSX、PDF。随包 Office 技能和独立 Python、Node、转换引擎及中文字体支持文档、表格、PPTX 制作与转换，执行仍受成员工具权限约束。Office/PDF 读取提供段落、工作表或页码来源；注册的原始成果可逐页预览。成果保留哈希与归档副本，可从任务详情打开。

## 记忆与外部工具

每个智能体通过 `manage_memory` 维护自己的长期记忆，管家维护自己的记忆及团队公共记忆，无需逐条人工审批。成员可以跨会话管理自己的记忆，管理不自动扩大原授权；检索与自动注入仍受会话授权限制。记忆支持成员、团队和共享范围；用户可在“记忆”页面编辑、删除和查看来源。候选整理使用独立后台上下文。长期记忆与对话摘要分别保存。

在“连接与设置 → 工具与 Skills”添加 MCP 或 HTTP 搜索服务。MCP 支持 stdio 和 HTTP；stdio 使用可执行文件绝对路径。检测成功后，仍需在对应 Bot 中明确授权该连接。搜索服务接受 GET 查询参数 `q`，可选 Bearer 凭据；也可通过 MCP 接入搜索工具。

外部代码助手可通过 MCP 接入并委派已有项目，原服务继续管理自己的审批。任务保留请求标识与外部任务标识，外部结果未知时阻止重复提交。

Skills 从本机 `SKILL.md` 导入，再由 Bot 选择启用。Skill 提供工作指引，App 工具执行权限仍由 Core 校验；agy 原生工具遵循其原生权限。

## 备份与恢复

在“连接与设置 → 运行与备份”创建备份。备份是包含 `manifest.json`、SQLite 数据和归档成果的**目录**；恢复时选择整个目录。

备份不包含 API/OAuth 凭据、原生运行时 profile 或原生 session 文件。恢复会替换当前工作台数据；请先创建当前备份并停止活跃任务。恢复后重新检测连接，重新提供所需凭据或完成授权，并确认工作目录。恢复的活跃任务标为中断，不自动重放；结果未知的外部操作仍需对账。

## 验收范围

“检测连接”验证授权、运行时兼容性及可获取的模型目录，不证明真实推理、工具执行、连续对话或取消已经成功。真实账号验收应在每个通道分别完成一次回答、一次授权工具调用、第二轮对话及运行取消。

`pnpm verify:providers --help` 提供独立验证工具。默认只输出准备情况，`--probe` 执行探测，明确 `--run --model <id>` 才进行真实推理。凭据仅从用户指定的环境变量获取，报告不会输出凭据或模型回答；ChatGPT 验证使用用户主动提供的完整 OAuth record，不读取桌面 vault。

日常 CI 在 macOS 与 Windows 执行现有测试、类型检查和源码构建。发布前手动运行 GitHub Actions 的“Validate desktop packages”门禁：生成两平台安装包，核对最终生产依赖及随包运行库，并在独立目录启动 Core、执行 Office 文档转换与预览检查。门禁使用 Windows runner 已有许可的 VC Redist，缺失时失败。窗口与托盘体验、真实模型调用，以及安装生命周期分别人工验收。
